# 本轮界面审核

日期：2026-10-19。设计来源与固定版本见 REFERENCES.md、references-lock.json。

照片模块加载修复：将照片持久保存合并到应用已有的 services/storage.js，移除独立 services/photos.js 及相关引用，照片链路改用 Promise，减少异步转译依赖。新增大小写敏感的微信式模块注册检查，应用、全部页面和组件共 17 个模块可在独立模块注册表中加载；照片流程及全部既有测试通过，WXML/WXSS 官方编译通过。该注册检查是本地模拟，不等于真实微信运行包验证。本机开发者工具 CLI 服务端口关闭，自动刷新编译缓存未执行，需在开发者工具中重新编译后确认。

后续调整：产品内名称统一为“哆哆记账”；首页字标用粉色猫爪替代两个“哆”字的口字旁，移除独立猫爪底标；账本名称从 44rpx 缩至 36rpx，账单入口与其同排；压缩月度卡片上下留白；陪伴卡片文案改为“日常有数，生活有猫”。本轮测试、官方编译与三种屏宽检查均通过。

账本与资产精简：账本首页、管理、创建及选择器均移除账本图标；创建/编辑账本取消分类管理，所有账本统一开放完整记账分类。默认数据改为一个日常账本、日常开支与安心储蓄两个资产账户，并移除旅行演示流水。资产页只保留“添加一个小金库”入口，账户使用九类本地 SVG 图标；小金库编辑页按用途选类别。旧版数据迁移保留全部现有账户、余额、流水、照片与活动账本，仅补充类别并统一分类。默认精简适用于首次运行/重置，升级不会自动删除已有账户。

新增新建账本、资产类别保存、旧数据迁移与重复打开验证；八个相关页面在 320、393、430 三种宽度下通过布局检查，九个 SVG 均成功加载；业务测试和微信编译通过。

照片与零余额调整：两个默认账户及新建小金库初始金额为 0，保留已有账户余额。账本明细显示该笔记录的照片缩略图，调用微信原生预览，仅展示当前流水照片。记账照片采用持久文件路径，保存失败不回退临时文件；保存期间禁用提交，并覆盖取消、拒绝隐私授权、文件保存失败、三张上限和字符串索引移除。照片保存在本机，不涉及上传或跨设备同步。

验证：新增 tests/photos.test.js，测试选择相机/相册、乱序保存完成仍保留图片顺序、提交等待保存、流水关联与重启后路径恢复、打开指定图片、取消与失败分支。全部业务测试与官方编译通过；照片布局在三种屏宽无溢出。preview/ledger-photos.png 使用既有品牌图作为布局样本，不写入真实默认账目。相机硬件、微信隐私弹窗与系统授权需要手机真机验收。

## 已落实

- 五个主页面统一纸色、森林绿、字体层级、留白、圆角与分隔线；次级页继承同一主题。
- 首页突出实际月度支出；收入与预算剩余为次级信息。无预算时改为“本月结余”，避免错误标签。
- 预算进度不会超过轨道宽度；极小的超预算也明确提示，不被百分比四舍五入掩盖。
- 首页提供金额隐藏开关，并持久化到原有设置。隐藏时预算数字和百分比文字同样遮蔽。
- 两张用户原图已复制进 assets/brand，并在真实页面引用。厨房三猫用于陪伴卡片；手绘字标用于个人页。图中原有食品评级与日期通过展示窗口排除，避免混入记账信息。
- 导航统一为线条图标、猫咪轮廓和集中记账入口；选中状态同时使用字重和标记。
- 清理旧的全局 !important 覆盖与重复问候卡；统一图表曲线与排行榜的收支色。
- 记账弹层使用可滚动详情区和固定数字键盘；底部留出安全区。主操作和图标按钮补充可访问名称，部分关键控件设置物理最小触控尺寸。
- 大金额可换行，明细备注和账户名称有溢出处理。
- GitHub 参考仓库、设计资料、原始图片、演示截图、脚本与测试从小程序上传目录中排除。

## 验证边界

本轮依据 Impeccable 等项目的检查维度进行源码和布局审核，没有运行外部项目的 Web 检测器。WXML/WXSS 编译属于真实微信编译验证；浏览器预览只近似还原原生布局，不是完整微信运行时。预览中的交互用于查看设计，真实业务逻辑由小程序和本地测试验证。

发布前仍需在微信开发者工具和手机上确认胶囊位置、安全区、原生日期选择器、相册/头像授权与画布表现；未进行真机验收。

## 复现

- 运行 npm test 验证业务和页面逻辑。
- 运行 node scripts/check-wechat.cjs 编译；若工具安装在其他位置，将 wcc-exec 目录作为第一个参数传入。
- 运行 npm run preview:build 后打开 preview/index.html 查看五个主要页面的布局近似预览。
- 可选截图脚本 scripts/capture-ui.cjs 需要可用的 Playwright 与 Chromium，结果保存到 preview/。
