# 哆哆记账微信小程序

一款可直接在微信开发者工具中运行的本地记账小程序。包含账本、资产、记账、图表、我的五个主要页面，以及账本编辑、月/年账单、资产编辑和设置。

## 本地运行

1. 安装并打开微信开发者工具。
2. 选择「导入项目」，目录选择本仓库根目录。
3. AppID 可使用测试号；项目已配置 `touristappid`。
4. 在项目目录运行一次 `npm run dev:configure`，再重新打开项目并编译。此步骤将本机私有配置中的调试基础库同步为项目指定的 `2.30.4`，保留个人 AppID 和其他设置。

数据保存在微信小程序本地存储中。首次运行会载入一组演示数据；可在「我的 → 设置 → 清空并恢复演示数据」重置。

首次运行或重置后，默认只有“日常账本”以及“日常开支”“安心储蓄”两个资产账户。账本不使用图标，也不单独配置记账分类。资产使用钱包、储蓄、现金、银行卡、支付、投资、旅行、应急、家庭九类线条图标。升级会保留已有账本、资产、余额和流水，并为旧资产补充类别。

两个默认资产账户和新建小金库的初始金额均为 0 元；升级不覆盖已有账户余额。记账详情中可点“照片”，选择拍照或从相册添加，每笔最多 3 张。照片先保存到本机，再关联到流水；账本“本月明细”会显示对应缩略图，点击可放大并滑动查看该笔的照片。

无需安装依赖。领域逻辑可通过 `npm test` 在本地验证。

账本明细支持向左滑动显示淡粉与奶油色的手绘橡皮擦，图案使用透明背景。点击后移除该笔记录，并回算原资产账户余额、当日支出、月度汇总和预算剩余；重复点击不会重复回算。向右滑动或点击记录可收起删除入口。图标外围保留 64px 宽、至少 52px 高的点击范围。

底部菜单使用页面内统一的悬浮导航，并在主页面显示时隐藏微信原生菜单，避免真机出现两排菜单。记账键盘采用四列等宽布局，日期、加号、减号与完成按钮等高，“记好了”文字居中。“我的”页面底部显示“哆哆记账”，并以小字标注“呼噜厨房出品”。更新后请重新编译并刷新真机调试包。

新增文件后若开发者工具提示 `module ... is not defined`，先重新编译；若仍运行旧代码，选择“清缓存 → 清除编译缓存”后再编译。此步骤只需刷新编译缓存，保留数据、文件与授权缓存。测试包含微信式模块注册检查；`scripts/check-wechat.cjs` 仅负责 WXML/WXSS 编译。

启动时若遇到 `getPermissionBytes` 回调中 `Cannot read properties of null (reading 'bg')`：本机 3.17.3/3.17.4 基础库的内部权限模块会直接读取空权限项的 `bg/fg`。项目使用不包含该读取分支的 2.30.4 作为开发者工具兼容调试版本；相机、头像和昵称接口仍受微信正常授权与校验。`project.private.config.json` 的优先级高于公共配置，且不会提交到 Git，因此更新代码后需要运行上述同步步骤。也可在工具的「详情 → 本地设置 → 调试基础库」手动选择 2.30.4，重新打开项目并编译。无需清除账本、照片或授权数据。这是开发工具兼容规避，不会固定手机微信的基础库版本；发布前仍需真机验证。

## 界面设计

采用猫咪手账风格：奶油方格纸、铅笔棕轮廓、胶带便签、鼠尾草绿与淡粉配色，以及中文手写体。风格参考 [Cat On Chair](https://catonchair.app/en/) 的温暖手绘氛围，界面与插画为本项目重新设计。账本、资产、记账、图表、我的，以及账本管理、编辑、账单和设置页使用统一主题。

全部 24 个支出类别、5 个收入类别、9 类资产账户，以及底部菜单、个人页菜单均使用本地手绘 PNG 图标，避免系统 emoji 的跨设备差异。图标与原创小猫插画位于 `assets/doodles/`，可编辑矢量源文件位于 `design/handdrawn/sources/`。账本、资产、记账页现在共用同一只三花猫哆哆：奶白底、左额橘斑、右耳深色斑、橘色侧身和深色尾尖，分别搭配书本、金币宝箱、笔记与茶杯。三个场景都能眨眼、呼吸和摇尾；不使用网络动画或计时器。粉色猫爪与“呼噜厨房出品”仍保留。

“我的”页头像为方形，新选的微信头像先持久保存到本机。头像与昵称需要分别选择：选完头像后若尚无昵称，会引导填写；点击昵称栏选择微信昵称，平台校验通过后保存，取消和校验失败会保留已有昵称。VIP 卡片文案改为“拍照数上限 / 照片漫画风 / 家庭账本”；当前会员仍为本地标识体验，本次未接入照片扩容、漫画处理或家庭同步服务。

手写字体使用霞鹜漫黑 v1.004 的离线子集，覆盖 GB2312 中文、拉丁字符、标点及应用文案，共 7,479 个字符；超出字集的生僻字使用系统字体补全。字体嵌入 `theme/handwriting.wxss`，无需网络下载。字体授权与来源见 `assets/fonts/OFL.txt`、`assets/fonts/NOTICE.md`；重建方式和设计说明见 [手账主题说明](design/handdrawn/README.md)。

已拉取的 GitHub 设计与审核项目、来源、版本和使用范围见 [设计参考](design/REFERENCES.md)。本地参考仓库位于 `design/references/`，不会进入小程序上传包。

本轮验证结果与真机验收边界见 [界面审核记录](design/AUDIT.md)。运行 `npm run preview:build` 可生成基于真实 WXML/WXSS 的浏览器布局预览，输出位于 `design/preview/`；业务运行仍以微信为准。

## 发布

1. 在微信公众平台注册小程序并取得 AppID。
2. 在微信开发者工具的项目设置中，将测试 AppID 替换为正式 AppID。
3. 配置用户隐私保护指引，按平台要求声明选中的照片与相机使用用途，用于用户主动添加记账凭证。用户需按微信和手机系统提示授权后使用拍照/相册功能。
4. 在开发者工具中点击「上传」，随后到微信公众平台提交审核和发布。

当前版本不依赖服务器，可直接以单设备本地版发布。微信昵称和头像由用户在「我的」页面主动选择；VIP 为本地体验状态，接入正式支付前不会产生交易。

拍照使用微信原生 wx.chooseMedia，查看使用 wx.previewImage；发布不会自动赋予相机权限，也不会在页面加载时启动相机。照片保存于当前设备的小程序文件空间，不自动上传或跨设备同步。参考 [微信官方 API 定义及说明](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。发布前应在手机微信中确认首次授权、拍照、返回记账、重启后查看照片的完整流程。

## 架构

- `pages/`：页面和交互
- `components/`、`custom-tab-bar/`：复用界面组件
- `store/`：账本、资产、流水的领域操作
- `services/`：持久化适配层
- `utils/`：日期与展示工具

业务状态与微信页面解耦，后续开发 App 时可以迁移领域模型，并替换存储层为服务端 API。
